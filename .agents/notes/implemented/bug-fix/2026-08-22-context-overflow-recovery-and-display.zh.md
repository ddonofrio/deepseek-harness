# Agent Note: 上下文溢出恢复与安全显示

状态：已实现

[English](2026-08-22-context-overflow-recovery-and-display.md) | 中文

## 问题

即使串行的 pre-step 压力检查没有看到当前用户输入，提供商仍可能报告完整请求超过模型上下文窗口。提供商措辞并不统一，直接把该诊断投影到客户端状态会暴露实现细节，而不是提供有用的恢复提示。

## 决策

AgentLoop 在当前步骤输入和请求头持久化后、发送冻结请求前，再执行一次现有的压力策略。如果压缩改变了会话，就重新构建请求。提供商适配器把带有实际消息大小的上下文错误归类为 `CONTEXT_WINDOW_EXCEEDED`，因此现有的有界溢出压缩重试仍然可用。客户端投影根据稳定错误码选择安全且可本地化的消息，不显示提供商诊断。

## 备选方案

- **要求提供商提供精确 tokenizer 进行预检：** 未采用，因为共享 LLM 接口没有提供该能力；现有 token-meter 策略和提供商响应是可用信号。
- **丢弃任意历史或当前提示：** 未采用，因为压缩必须保留模型可见内容和成对的工具调用单元。
- **只修改客户端文字：** 未采用，因为未分类的溢出仍会绕过恢复路径。

## 结果

接近上下文上限的请求在发送前可能额外执行一次压力检查和压缩。启发式预检不会取代提供商权威的溢出处理，因此适配器仍会规范化提供商响应，循环也保留有界重试。客户端可见的失败消息保持可操作，并且不包含原始的提供商上下文限制措辞。
